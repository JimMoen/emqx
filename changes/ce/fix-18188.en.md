Hardened the plugin framework against malicious or tampered plugin packages.

* Fixed an authorization bypass where `emqx ctl plugins install` could install a plugin package without a prior `plugins allow` grant. The CLI now enforces the same allow gate as the HTTP upload API, and consumes the grant upon successful installation.
* Plugin API callback responses can no longer set browser-sensitive HTTP headers (such as `set-cookie`, `location`, `access-control-*`, `content-security-policy`, and other authentication or security policy headers), which could previously undermine the Dashboard's origin and cookie policy.
* Added the `plugins.package_limits` configuration to bound plugin package extraction: `max_package_size` (default `10MB`), `max_decompressed_size` (default `50MB`), `max_file_count` (default `10000`), `max_path_depth` (default `32`), and `max_extraction_time_ms` (default `60s`, also used as the RPC timeout for cluster package copying). Packages violating these limits are rejected before or during extraction. Tar entries escaping the install directory (path traversal) are also rejected.
